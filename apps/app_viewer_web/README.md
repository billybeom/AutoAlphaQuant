## 2. Q-D — 무엇을 결정하는가

> **질문**: v1에서 웹·데스크탑 뷰어를 아예 뺄 것인가.
> **선반영 없음** — 다른 미결과 달리 권고안이 정해져 있지 않습니다. 발주자 판단 사항입니다.

| 선택 | 결과 |
|---|---|
| **(a) v1에서 뺀다** | 이 폴더 삭제 · `FeatureFlags.webViewerEnabled=false` 고정 · 화면 명세의 웹 레이아웃 분기 제거 → 만들 화면이 줄어듭니다 |
| **(b) v1에 넣는다** | `app_viewer_ios`와 같은 패키지 집합을 살리고, §3의 웹 고유 제약을 온보딩·보안 설계에 반영해야 합니다 |

## 3. 웹 타깃 고유 제약 — (b)를 고를 때 같이 걸리는 것

| 제약 | 내용 |
|---|---|
| **키를 둘 자리가 없다** | 브라우저에는 OS 키체인에 해당하는 안전한 저장소가 없습니다. 그래서 웹은 iOS보다 더 강한 «읽기 전용»입니다 — 브로커 키는 어떤 형태로도 웹에 오지 않습니다 |
| 세션·인증 | Supabase 세션을 브라우저에 두면 기기 분실 시 회수 경로가 폰과 다릅니다(X1 기기 이전과 맞물림) |
| 푸시 | 웹 푸시는 브라우저·OS별로 신뢰도가 갈립니다. **P0 알림 경로로 삼을 수 없습니다** |
| 배포 | 정적 호스팅이면 URL을 아는 사람이 접근합니다 — 인증 게이트가 필수 |

## 4. 빌드 제외 규칙 — (b)를 고르더라도 그대로

viewer 타깃의 공통 규칙입니다(`app_viewer_ios/README.md` §2와 동일).

- 🔴 `trading_runtime` · `broker_gateway` · `core_engine`을 **`pubspec.yaml`에 넣지 않습니다** — 넣지 않으므로 주문·엔진 코드가 웹 번들에 컴파일되지 않습니다.
- 🔴 `ui_safety`는 **킬스위치 «발동»만**. 해제(48h 대기·체크리스트 7항) 화면은 operator 전용입니다.
- 🔴 `ui_settings`의 **키 입력 위젯은 라우팅에 넣지 않습니다**(§3 첫 줄과 같은 이유).

## 5. 네이티브 폴더는 아직 없습니다

```bash
cd apps/app_viewer_web
# ⚠️ Q-D가 「포함」으로 확정된 뒤에만 실행하십시오.
# ⚠️ 기존 pubspec.yaml·README.md·lib/main.dart를 덮어쓸 수 있습니다 — 임시 폴더에 만들어
#    web/ 만 복사해 오는 편이 안전합니다.
flutter create --platforms=web --project-name=app_viewer_web .
```

- `android/`·`ios/`는 이 타깃에 만들지 않습니다.
- ⚠️ 데스크탑(windows/macos/linux)까지 공유하기로 하면 `--platforms`에 추가하되, **그것 역시 Q-D 범위 안의 결정**입니다. 임의로 늘리지 마십시오.
