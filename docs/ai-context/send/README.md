## A. Bob에게 보내는 법 — 7걸음

1. **Bob을 엽니다** — 작업 공간(프로젝트 폴더)으로 `C:\Work\Bob\AutoAlphaQuant`를 엽니다. 이 폴더 안에 `docs/ai-context/`(문서 5부·프롬프트)와 `packages/domain_contracts/`(계약 코드·픽스처)가 이미 있어 **따로 첨부할 것이 없습니다.**
2. **패킷 파일을 엽니다** — 예: `docs/ai-context/send/R1-Bob-J1.md`. «3. 붙여넣을 본문»의 구분선 다음 줄부터 «3-1» 직전까지 **전부 복사**합니다(프롬프트 원문 + 지시문이 한 덩어리입니다).
3. **Bob 채팅에 붙여넣고 보냅니다.** 본문은 고치지 않습니다. Bob이 «어느 파일을 읽을까요?»라고 물으면 «`docs/ai-context/` 안의 문서만»이라고 답합니다(청사진·엔진 명세는 주지 않습니다).
4. **기다립니다.** Bob이 파일을 만들고 `melos.bat run analyze`·`melos.bat run test:contracts`를 돌립니다. 빨간색이 나면 **Bob에게** «검사 결과대로 고치세요»라고만 합니다(발주자가 코드를 고치지 않습니다).
5. **받습니다** — Bob이 만든 것: ① PR(브랜치 `ui/m6-j1-timeline`, 제목 `[M6] J-1 매매일지 타임라인`, 본문 5섹션) ② 질문 파일 `docs/ai-context/inbox/J1_questions.md` ③ 스크린샷 4장 이상. R0 카드는 PR 없이 «결과 텍스트» 또는 «질문 파일»만 옵니다. 🔴 **R1 실측 교훈(2026-09-16)**: Bob이 «로컬 브랜치에 구현했다 · PR은 만들지 않았다»로 끝내면 그 자리에서 **「`melos.bat run format` 돌리고 커밋·푸시·PR까지 하세요. 질문은 파일 `docs/ai-context/inbox/J1_questions.md` 로」**라고 한 번 더 말합니다 — PR·질문 파일이 없으면 Claude 는 검사할 «제출물»이 없는 상태로 코드를 봐야 합니다.
6. **5분 눈 검사**(코드 과제만) — ① 픽스처 JSON의 문구와 화면 문구가 같은가 ② 타임라인에 손익 숫자가 없는가 ③ 명세에 없는 요약 숫자를 만들지 않았는가 ④ 킬스위치 같은 안전 화면을 그리지 않았는가. 하나라도 «예»면 7번에서 반려를 부탁합니다.
7. **Claude에게 넘깁니다** — 패킷 «4. 받은 뒤 Claude에게 보낼 문장»을 그대로 보냅니다. 예:
   ```
   R1-Bob-J1 결과: PR #3, 질문 파일 docs/ai-context/inbox/J1_questions.md — 병합 검사하고 질문 반영해줘
   ```
   반려하고 싶으면 뒤에 「…는 검수 4항 ②에 걸림, 반려 문구 써줘」를 덧붙입니다.

## B. Gemini에게 보내는 법 — 두 갈래

**먼저 `R0-Gem-ENV.md`로 방식을 정합니다.** Gemini CLI가 설치돼 있으면 ⓐ, 웹 채팅만 쓸 수 있으면 ⓑ입니다.

- ⓐ **CLI(권장)** — 터미널에서 `cd C:\Work\Bob\AutoAlphaQuant` → `gemini` 실행 → 패킷 3번 본문 붙여넣기. 이후는 Bob과 같습니다(파일을 직접 만들고 명령을 돌리고 브랜치를 팔 수 있음). PR은 Gemini가 못 만들면 발주자가 GitHub에서 «Compare & pull request»로 만듭니다.
- ⓑ **웹 채팅** — ① 패킷 «2. 첨부할 파일» 순서대로 파일을 첨부(`prompt_M7.md` → `00` → `01` → `03` → `08` → `contracts_bundle.md` → `fixtures_README.md`) ② 3번 본문 붙여넣기 ③ 지시문 끝에 한 줄 추가: 「결과는 **파일별로 `경로` 한 줄 + 전체 코드**로 출력하세요. 부분 diff 금지. 마지막에 질문 목록 표.」 ④ 받은 코드를 발주자가 그 경로에 저장 → `melos.bat run analyze`·`melos.bat run test:contracts` 실행 → 빨간색이면 결과를 Gemini에 다시 붙여 고치게 함 → 브랜치·커밋·PR은 발주자가 만듭니다(제목·본문 규칙 동일). 질문 표는 `docs/ai-context/inbox/S7-1_questions.md`로 저장.
- 그다음 **Claude에게 넘기는 문장은 Bob과 같은 형식**입니다(패킷 4번).

## C. Claude가 받은 뒤 하는 일 (발주자는 기다리기만)

1. 기계 검사(analyze · 계약 테스트 · CODEOWNERS) → 빨간색이면 반려 문구를 써서 돌려드립니다.
2. 사람 판단 4항(계산·문구 생성·손익 노출·안전 화면 접근).
3. 질문 목록을 계약(01)에 반영 — 확정할 것은 01·픽스처·`domain_contracts` 코드·테스트 갱신 → `docs/ai-context/` 재조립(새 «팩 판»).
4. 병합(squash) → `rounds.md` 갱신.
5. 핸드오프·메모리 기록, 커밋(푸시는 지시 시).
6. **다음 카드 준비** — 「다음 카드 R<n> 보내도 됩니다」와 함께 새 패킷을 `send/`에 둡니다.

발주자가 받는 보고는 네 줄입니다: 병합됨 / 반려(문구 포함) / 질문 반영 결과 / 다음 카드.

## D. 절대 규칙 6

1. 실키·계좌번호·비밀번호는 어떤 AI에게도 붙여넣지 않습니다.
2. 패킷 3번 본문은 고치지 않습니다(07 원문). 범위·파일명만 Claude가 다음 패킷에서 바꿉니다.
3. 한 화면은 한 AI에게, 한 PR = 한 화면(그룹).
4. 병합은 Claude(또는 발주자)만. Bob·Gemini는 병합하지 않습니다.
5. 픽스처·뷰모델 골든은 AI가 고치면 반려. 위젯 골든(PNG)만 그 PR에서 최초 베이스라인 허용.
6. 청사진·`06_시스템설계`·`06/07/09~12` 문서는 화면 AI에게 주지 않습니다.
