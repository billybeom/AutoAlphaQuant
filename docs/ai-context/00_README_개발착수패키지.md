## §5. 경계 규칙 3과 기계적 강제 — "빌드가 막는다"

경계 규칙(청사진 §1)은 **문서로 부탁하지 않고 빌드로 막습니다.** 위반이 "잘못된 화면"이 아니라 **빌드 실패**로 나타나야 리뷰가 병목이 되지 않습니다(청사진 §9-2).

| 규칙 | 무엇을 막나 | 기계적 강제 |
|---|---|---|
| **① 계산·판정·사유 문구는 Claude 단일 소스** | 화면이 재계산해 엔진과 다른 숫자를 띄우는 사고 | `ui_*`의 `pubspec.yaml`에 `core_engine`·`decimal`·`broker_gateway`를 **의존으로 넣지 않음** → import 자체가 컴파일 실패 / 금액·비율 타입 산술 lint(뷰모델의 `Money`·`Ratio`에 연산자 미정의) / **뷰모델 골든 스냅샷 테스트**(계약이 바뀌면 스냅샷이 깨짐) / 사유 문구 하드코딩 탐지(CI에서 한글 문구 리터럴 grep) |
| **② DB 쓰기 주체는 엔진 하나** | 앱이 DB에 직접 써서 멱등성(NR-1)·일일 대사(FR-801)가 무너지는 것 | `ui_*`에 DB·Supabase 클라이언트 의존 금지, 쓰기는 `domain_contracts`가 노출한 **명령 API 인터페이스**로만. 뷰어 쓰기는 append-only 명령·이벤트 테이블 4종 + RLS로 서버에서도 한 번 더 막음 |
| **③ 안전 화면은 "불편이 사양"** | 킬스위치 48h 대기·체크리스트 순차 통과가 "UX 개선"으로 침식되는 것 | M5·X1·X5 화면 파일은 Claude 소유 패키지 **`ui_safety`**(§4 확정)에 두고 CODEOWNERS로 잠금. 웹·데스크탑 타깃은 브로커·주문·키 코드가 **빌드에서 제외**(코드 리뷰로 대체 불가) |

**🔵 P 회차 신설 — 표시 계약 4건의 기계적 강제 (⬜ 계약 테스트 실물 신설 대기)**

P 회차는 규칙을 하나도 바꾸지 않고 **표기 규약 4건**을 세웠습니다. 그런데 그것을 잡는 게이트가 **지금은 없습니다** — 현행 C-4는 `Money`/`Decimal` 필드의 산술만 보고, C-5는 `labels.dart`를 제외한 한글 리터럴만 봅니다. 세율(`double`) 곱셈도 `10.63` 같은 숫자 리터럴도 어느 검사에도 걸리지 않습니다. **없는 강제를 있다고 적으면 다음 구현자가 안심하고 어깁니다.**

| 표시 계약 | 무엇을 막나 | 필요한 기계적 강제 |
|---|---|---|
| **세후 층을 접지 않는다** | 화면이 층 간 차액을 빼거나(10.85−10.63) 세 층을 한 숫자로 줄여 「세후 = n%」로 그리는 것 | ⬜ **신설 필요** — `ui_*` 안에서 세후 값 필드(`double`) 참조 0건 · 숫자 리터럴 0건 · 갈래 정확히 1개 · `steps`를 코드로 층 수 고정하지 않음. 골든 `aftertax_full_S7` 대조 병행 |
| **회계 기준을 섞지 않는다** | 한 표·한 합계에 서로 다른 기준(`accounting` / `engineColumn`)의 비중이 들어가거나, 화면이 A와 POT를 더하는 것 | ⬜ **신설 필요** — 한 위젯트리에서 서로 다른 기준의 비중 혼합 탐지 + `ui_*`의 A+POT 산술 탐지(C-4는 `double`을 잡지 못하므로 **탐지 대상을 `*Pct`·`*Ratio`·`cagr*` 이름의 `double` 필드까지 확장**해야 함) |
| **램프 두 뜻을 섞지 않는다** | 「램프 L1」(운영)과 「초기 진입 6개월 분할」이 한 낱말로 붙어 «L1인데 왜 1/6이지» 식 문구가 나오는 것 | ⬜ **신설 필요** — `lib/l10n/labels.dart`의 키·문자열 **전수 검사**로 «램프»가 접두(«운영 램프»/«초기 진입») 없이 단독으로 쓰인 항목 0건. 🔴 C-5는 `labels.dart`를 예외로 두므로 **C-5로는 잡히지 않습니다** — 별도 검사 항목이어야 하고, `ui_*` 전역 경고로 만들면 진짜 위반이 경보 피로에 묻힙니다 |
| **기각된 선택지를 되살리지 않는다** | 기각 항목(환헤지 오버레이 등)이 프리셋·실험 토글·설정 스위치로 되돌아오는 것 | ✅ **이미 있음** — `SettingsActionId` 인자 스키마 화이트리스트(01 §4-3)가 화면에서 부를 수 있는 인자를 열거로 닫습니다. 여기에 설정 화면 리뷰 체크를 더합니다 |

> 🔴 **번호 주의** — P 회차 검토 문서는 위 신설 검사를 «C-18·C-19»로 불렀지만, **X7이 `C-18`~`C-29`를 선점**했습니다(01 §7 · 17종 → ~~29종~~ 🔵 **31종**). ~~P 회차 신설분의 번호는 **`C-30` 이후**이며 ⚠️ **M2-8에서 확정**합니다 — 이 문서가 번호를 만들지 않습니다.~~ ✅ **번호는 01 §7이 확정했습니다(2026-09-07)** — 위 표 1행(세후 층) = **`C-30`**, 2행(회계 기준) = **`C-31`**. 3행(램프 라벨)은 여전히 번호 없는 `labels.dart` 전수 검사이고, 4행은 이미 있는 강제입니다. ⬜ 남은 것은 번호가 아니라 **구현**(M2-6)이며, 구현 전까지 위 표의 «⬜ 신설 필요»는 그대로 참입니다 — 이 문서가 번호를 만들지 않는다는 원칙도 그대로입니다(번호를 만든 것은 01입니다).

## §6. 금지 4항 · 검수 4항

**금지 4항 (다른 AI에게 그대로 전달)**

1. **화면에서 재계산 금지** — 수익률·비중·손절선·기여도 전부 M2가 준 값을 표시만 합니다.
2. **사유 문구 생성 금지** — 규칙 트리거·청산 티어·거부 사유 문구는 엔진이 만든 문자열을 그대로 씁니다. 코드→문구 매핑도 M2 소유입니다. **유일한 예외는 정적 UI 라벨**(「닫기」·「기간」처럼 데이터가 바뀌어도 글자가 같은 것)이고 패키지마다 `lib/l10n/labels.dart` 한 파일에 모읍니다 — 경계 조문은 `01` §1-5, 검사는 C-5입니다.
3. **홈·알림·위젯에 손익 금지** — 결정 8. 홈에 두는 숫자는 손익이 아니라 *슬리브별 목표 대비 편차·밴드 여유·과정 지표 3개*입니다.
4. **안전 화면 접근 금지** — M5·X1·X5 화면과 재개 게이트·정정 마법사는 건드리지 않습니다.

**검수 4항 (병합 전 Claude가 확인, 하나라도 예면 반려 — 핸드오프 §5-5)**

- 화면이 계산하나? / 사유 문구를 지어냈나? / 홈에 손익이 보이나? / 안전 화면을 건드렸나?

| **정직 기대** 🔵 P 회차 | 전 계좌 세후(인출세 16.5%) − 낙관 감액 = **10.2% 안팎**, 최악(POT 일반계좌·종합과세 38.5%) **9.7%**. 구 «10.4% 안팎»(인출세 미포함)을 **대체**하며 **앱 어디에도 숫자를 상수로 두지 않는다**(엔진 문자열) |
| **운영 방식(OperatingMode)** 🆕 X7 | **누가 주문을 집행하는가** — `autoTrade`(엔진) · `advisory`(사람). `RunMode`(어느 계좌·어느 서버인가)·`ExecPolicy`(이번 배치가 어디까지 나가는가)와 **직교**한 세 번째 축이며, 값을 바꾸는 유일한 경로는 `M5-10` 게이트·`M5-11` 위저드다. 🔴 **엔진의 어떤 안전 강등도 이 값을 바꾸지 않는다**(강등은 `ExecPolicy` 전용) — 그래야 «수동을 고른 사람에게 자동 매매가 켜지는» 사고가 표현 불가능해진다 |
| **투자 안내(수동 매매) 모드** 🆕 X7 | `OperatingMode.advisory`. 엔진은 규칙대로 계산해 **무엇을 언제 얼마나** 매매할지 «안내»를 내고, 실제 주문은 사람이 증권사 앱에서 낸 뒤 앱에 **수기로 기록**한다. 화면 라벨은 «투자 안내»(긴 형태 «투자 안내(수동 매매)»). 🔴 앱 전체에서 «추천»·«권유»·«자문»·«시그널» 단어 금지 — 1인 자기 사용이라 투자자문업이 아니지만 문구가 권유로 읽히면 곤란하다. 표현은 «내 규칙의 계산 결과» |
| **안내(advice)** 🆕 X7 | 안내 1건 = **계획**이지 사실이 아니다. `order_intents` **뒤**에서 갈라져 나오며 생애는 `AdviceStatus`(`open`·`partial`·`filled`·`skipped`·`expired`·`superseded`·`revoked`) — 뒤 4종은 terminal이라 어떤 경로로도 되살아나지 않는다. 🔴 **안내와 원장(체결)을 한 목록에 섞지 않는다** |
| **수기 체결(manual fill)** 🆕 X7 | 사람이 증권사 앱에서 낸 주문의 체결을 앱에 적은 것. 🔴 **별도 표를 만들지 않고** 기존 `executions`에 provenance(`FillOrigin`·`FillKind`)를 붙여 **한 스트림**으로 들어간다 — 그래야 `positions`·성과·대사 파생이 한 줄도 안 바뀐다. 정정은 수정이 아니라 **역분개(`reversal`) + 재기재(`restatement`)**이고 진입은 `M5-12`(M5 소유)다 |
| **지연 이행** 🆕 X7 | 유효기한이 지난 뒤 도착한 기록. 🔴 **거부하지 않는다** — 체결은 사실이고 거부하면 원장이 거짓이 된다. 안내는 `expired` 그대로 두고 `advice_id`를 **참조로만** 실으며(`ADVICE_LATE_FILL`), **재량 예산 미차감·정식 저널 불요·`note` 불요**. 이행률 라벨에 «(지연 이행 n건 포함)»을 엔진이 붙인다 — **지표는 정직하게, 벌점은 없다** |
| **이행 갭(execution gap)** 🆕 X7 | 「안내한 것」과 「실제로 한 것」 사이의 거리. 지표 3종 = **이행률**(건수·금액 가중, 지연 이행은 분자에 별도 계상) · **중앙값 지연**(거래일) · **가격 갭**(🔴 **bp만 — 금액은 결정 8 위반**). 운반 타입은 `ExecutionGapReport`(01 §2-11 · 창구 `ExecutionGapRepository`)이고 판정·문구는 전부 엔진이 만든다. 🔴 **노출 범위는 월간 리포트 ⑧ 부기와 `S7-10` 안내 이행 리포트뿐**(결정 ㉟) — 홈·알림·위젯에 이행률을 띄우지 않는다. 🔴 자동매매 모드에서는 이 지표가 성립하지 않는다(안내 자체가 없다) |
| **허용 범위** 🆕 X7 | 수기 기록을 받아들이는 두 겹의 창. ① **가격** = 그날 그 종목의 [저가, 고가] 밖이면 거부(`PRICE_OUT_OF_RANGE`) — «자유롭게 수정»의 유일한 하드 한계 ② **거래일** = [안내 발행 거래일, `validUntilDate`] 창 밖이면 거부(`FILL_DATE_OUTSIDE_ADVICE_WINDOW`). 🔴 두 축을 함께 닫지 않으면 날짜를 옮겨 유리한 가격을 통과시키는 곱셈이 열린다. 사용자가 검증 강도를 고르는 컨트롤(«시간외·단주» 체크박스)은 폼에 두지 않는다 — 거부 뒤 엔진이 판정해 연 별도 경로만 있다 |
| **원장 실사(self-audit)** 🆕 X7 | 대사의 수동판. 브로커 API가 없을 때 진실을 주입하는 유일한 통로는 사람이 증권사 앱을 읽는 것이다 — 월 1회 `L-3`에서 종목·수량·원화현금 + 「이것이 전부입니다」 확인 1단계. 차이는 `ledger_diff(pair='CANON_SELF_REPORT')`가 되고 해소는 **X5 정정 마법사를 그대로 재사용**한다(새 마법사를 만들지 않는다 — 마찰의 형태가 같아야 습관이 하나다). 🔴 `SELF_AUDIT_DUE`는 **차단이 아니라 상태 표식**이다 |
| **시스템 밖 자산(external holding)** 🆕 X7 | 실계좌에 있으나 이 시스템이 관리하지 않기로 한 종목·수량. 대사에서 **차감**되며(없으면 「제외」를 고른 순간 대사가 영구 불일치가 되어 전 주문이 막힌다) 등록에 `decision_id` 필수다. `H-1`은 `HoldingScope`로 «관리 대상»과 이것을 **한 목록에 섞지 않는다** |
| **예산 차감 명령 2종** 🆕 X7 | `recordManualFill(adviceId == null)`(안내 밖 수기 매매) · `skipAdvice(reason ∈ {intentionalPause, priceUnacceptable})`(의도적 거부). 🔒 **`ui_safety`(M5) 소유 경로에서만 호출**되며 M5-6 5단계 마찰을 지난다. 기록(사실 추가)과 미이행 «분류»는 M6이지만 **원장 재해석 + 재량 예산 차감은 M5**다. 🔴 방치(lapse)에는 예산을 걸지 않는다 — 「의도적으로 규칙을 거스름」과 「못 함」은 조치가 다르므로 다르게 말한다 |
| **개시 원장(OPENING_BALANCE)** 🆕 S1~S9 검증 | 안내 개시 게이트(`M5-10`)·집행 주체 전환 위저드(`M5-11`)의 **「초기 보유 실사」가 원장의 시작점이 되는 규약**. 사람이 신고한 종목·수량이 개시 원장 행이 되고, 그 뒤의 평균단가·손절 기산점·성과 기준일이 전부 이 행에서 출발한다 — 실사를 «참고 입력»으로만 두면 첫 배치가 **이미 가진 것을 다시 사는** 사고가 난다. 🔴 조문의 정본은 **01 §10-3**이고, 「개시 단가 = 기준일 종가 · `positions.entry_decision_id` 부여 · 손절 기산점」은 **엔진 규칙**이라 `06` §4 SPEC 개정 배치 계획에도 함께 등재된다(01만 고치면 두 정본이 생긴다). 이 문서는 **낱말만** 고정한다 |
| **운영 파라미터(operating parameter)** 🆕 S1~S9 검증 | 전략 `config_hash` **밖**에 있으면서 운영을 바꾸는 값 — **월 납입 운영값**(10만원)·**「다음 납입 주기」의 기준일**(`contribution_day`, ⚠️ 값 확정 대기 §8-5 V-1) 따위. 성질 셋: ① 앱 설정에서 **언제든 바꾼다** ② **정정은 수정이 아니라 새 행**이고 변경 이력 표에 남는다(다음 주기부터 적용) ③ 🔴 **화면·픽스처·문서가 값을 상수로 알지 않는다** — 설정·엔진에서 읽습니다. 골든벡터·재현성 게이트는 이 값을 보지 않으므로 값이 바뀌어도 전략 판정은 흔들리지 않는다 |

> 🔴 **실측 수치를 인용할 때는 어느 실행의 값인지 반드시 병기합니다**(🔵 P 회차 규약) — «1억 일시 투입·무납입 정본»과 «실전 조건(시작 2,000만 + 월 납입)»은 **다른 실행**이고, 조건을 밝히지 않은 수치는 화면·문구·주석에 쓰지 않습니다. 예: 연금 한도 소진으로 초기 진입 램프가 3개월에 끝나는 것은 1억 가정에서만 참이고, 실전 조건에서는 한도 구속이 0/25년이라 조기 종료가 없습니다.

> 🔴 **편집 심사 규칙 4** 🆕 X7 — 어떤 조문을 넣기 전에 «이 규칙에서 **가장 게으른 사람이 가장 유리한가**»를 한 번 통과시킵니다. 정직한 행위(늦게라도 기록 · 명시적 미이행 선언 · 성실한 실사 · 대사 키 등록)가 회피(방치 · 미등록 · 베끼기)보다 비싸면 **그 조문은 반려**입니다. 이 규칙이 없어 실제로 뒤집혔던 자리: 만료 뒤 기록을 거부하면 규칙을 지킨 사람이 「안내 밖 매매」로 분류돼 예산을 잃고 정식 저널까지 쓰는데, 아무것도 안 한 사람은 공짜였습니다.
