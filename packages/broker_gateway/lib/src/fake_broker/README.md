# `lib/src/fake_broker/` — FakeBroker 시나리오 (**예정 — 아직 비어 있다**)

실제 브로커를 부르지 않고 주문 경로 전체를 돌려보기 위한 **가짜 브로커**다. DRY_RUN·SIM 기간의 유일한 상대이며, 골든벡터가 «계산이 맞는가»를 보는 것과 달리 여기는 **«이상한 응답이 왔을 때 무너지지 않는가»**를 본다.

## 담을 시나리오 (예정)

| 갈래 | 시나리오 |
|---|---|
| 정상 | 전량 체결 · 부분 체결 · 지연 체결(FILL_LAG) |
| 거부 | 주문유형 화이트리스트 밖(SAF-404) · 잔고 부족 · 장 마감 |
| 모호 | 응답 유실 후 재조회에서 체결 확인(UNKNOWN 해소) · 타임아웃 |
| 방어 | 같은 멱등키 재발주 → **`prevented`**(NR-1이 작동한 것) |
| 장애 | 토큰 만료 · 유량 초과 · 브로커 5xx 연속 |

## 🔴 규칙

1. **실키·실계좌를 쓰지 않는다.** 응답도 합성값이다.
2. **`prevented`를 실패로 만들지 않는다** — 이중 발주 차단은 성공 경로다.
3. **모호한 응답을 «실패»로 단정하지 않는다.** UNKNOWN은 해소 보드로 넘어가는 별도 상태다.
4. 이 폴더의 시나리오는 **DRY_RUN 이탈 판단의 근거가 아니다.** 그 게이트는 골든벡터(`core_engine/test/golden/`)다.
